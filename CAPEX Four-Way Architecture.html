Four-way reconciliation on a graph, where the rules decide and a person approves

An email agent picks the PO, GRN, external audit report and supplier invoice off the AP mailbox, routes each to its own parser, and lands them as connected nodes rather than rows in five tables. Deterministic rules set by the organisation compile to GSQL and return their own evidence trail. Only what the rules decline is adjudicated, a person approves it, and the decision pair becomes precedent for the next one.

Low-level design

Classes and how they connect

The reconciliation layer is a set of small pieces with one job each. Graph sources share one protocol, so the same rules run against the live graph and against a local mirror used for back-testing a rule change before it is published. Select a class for its responsibilities and file.

Deployment

Where each part runs

The API, the pipeline workers, the parsers, the secrets and the audit trail stay on the client's tenant. Four external services are called over HTTPS with the minimum each needs. Rule sets are versioned, and a rule change is back-tested on the mirror before it is published.
